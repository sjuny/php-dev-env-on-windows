# プログラム言語共通コード生成規約

プログラムコードを生成する際には、プログラム言語を問わず、**必ず**以下の規約に従う。

## 1. 変数や定数

### 1-a. マジックナンバーを使用しない

- マジックナンバーは**絶対**に使用しない。
- 数値は、内容が分かる変数や定数に代入して利用する。

### 1-b. 文字リテラルを関数やメソッド内で使用しない

- 文字リテラル「"<文字>"」は、処理定義内では利用しない。
- 文字リテラルは、以下の箇所で定数や変数に代入して、その定数や変数を処理で利用する。
  - 定数の定義ファイル
  - 設定ファイル
  - ソースファイルの冒頭
  - クラスのプロパティ

- 但し、変数展開のコード全体はは定数にしない。プレイスホルダーはそのままでリテラル値のみ定数にする。
  - 例：("{1}:{0}", MESSAGE, COUNT)

### 1-c. 変数名に略字は使用しない

- for ループのカウンタ変数以外で、変数名の略字は使用しない。
- 意味をなさない文字列にもしない。
  - 例.cfg、usr

### 1-d. 変数名は短く命名する

- 単語を3つ以内で変数名は命名する。
- 関数、モジュール名、クラス、メソッドで何を扱うか文脈を与えることで、変数名自体は短くする。

### 1-e. 広域スコープの参照変数は定数化

- 関数やクラスを跨ぐ広域スコープで参照する変数は定数にする。
- 定数であることが直感的に判別しやすくする為、すべて大文字でスネークケースにする。

### 1-f. 複数の値を代入することがわかる変数名をつける

- 配列、リスト、辞書など一つの変数で複数の値を格納する場合、形式が分かる名前をつける。
  - 複数形、-mapなど。
  - 配列やリスト自体を複数で扱う場合は、個別の配列やリストは-listにして、複数扱う場合はlistsにする。

### 1-g. 定数のコメント

- 定数を定義したら、**必ず** 何をするための定数かコメントを入れる。

### 1-h. Boolean変数名

Boolean値を保持する変数は、状態または判定内容が分かる名前にする。

```powershell
$IsInstalled
$HasConfiguration
$ShouldRestart
$CanConnect
```

意味が不明確な名前は使用しない。

```powershell
$Flag
$Check
$Result
```

## 2. 関数やメソッド

### 2-a. 関数やメソッド内に処理を定義する

- 処理は、ソースファイルのトップレベルに**絶対に**記載しない。
- 処理は、**必ず** 関数やメソッド内に定義する。

### 2-b. 関数またはメソッドの処理目的の細分化

- 目的の異なる処理を関数やメソッドに定義しない。
- ただし、複数の処理を呼び出し、流れを作る関数やメソッドは例外とする。
- 関数は単一責任の原則に従う。

### 2-c. 引数の数を少なく保つ

- 原則として、引数は 3 つ以下にする。
- 引数が4つ以上になる場合は、引数として構造体またはクラスを使う。

### 2-d. 早期リターンを使用してコードをシンプルに保つ

- 特定の条件の処理が長くなり、ブロックが長くなる条件分岐を処理する場合は、早期リターンを使用してコードをシンプルかつ簡潔に保ちます。

### 2-f. 関数やメソッドの定義コメント

- クラス、メソッド、関数の定義の開始部分には、**必ず** 以下の内容を示すコメントを記載する。
  - 処理の目的
  - 処理の概要
  - 引数
  - 戻り値

### 2-g. 純粋関数と副作用

- 関数とメソッドは原則、純粋関数で定義する。
- ファイル作成、ファイル削除、設定変更、プロセス起動などの副作用を持つ関数は、関数名およびヘルプでその動作を明確にする。
- 状態を参照する関数と、状態を変更する関数を混在させない。

### 2-h. 処理の起点関数の定義と呼び出し方

- 実行スクリプトの処理の起点関数を必ず定義する。
  - 名称はプログラム言語別の規約に委ねるが、mainに関する文字をつける。
- 処理の起点関数は一文で呼び出し、例外捕捉処理は関数内で定義する。
- 処理の起点関数は、呼び出元にステータスコードとして返却する。

## 3. コードブロック

### 3-a. ブロックのネストを浅く保つ

- 条件ブロックとループブロックのネストは 2 レベルに制限してください。2 レベルを超える場合は、ロジックを別の関数またはメソッドで定義し、それを呼び出してください。

### 3-b. ブロック内の行数を減らす

- 関数、メソッド、条件、ループの行数は最大 30 行に制限してください。これを超える場合は、ロジックを別の関数またはメソッドで定義して呼び出してください。
- ただし、複数の値をまとめて設定する場合は、このルールの例外です。

### 3-c. ブロック内のコメント

- 関数やメソッドに限らず、ブロック内の処理が複数ある場合は、**必ず** 処理目的ごとにコメントを記載する。

## 4. ソースファイル

### 4-a. ソースファイルの行数

- １つのソースファイルの行数が 500 行を超えたら、処理を分割する。

### 4-b. 実行ファイルのコメント

- 実行起点となるソースファイルの先頭には、以下のコメントを**必ず**記載する。
  - 処理の目的
  - 処理の概要
  - 引数
  - 戻り値
  - コマンドでの呼び出し方法

## 5. その他

### 5-a. コメントの言葉

- コメントの言葉はできるだけ仕様書で利用されている言葉を利用する。

### 5-b. 状態判定に例外を利用しない

- 状態判定は bool や int で戻り値を返す関数やメソッドを利用する。
- 例外の発生で状態判定をしない。
- 但し、例外でしか状態を判定できない言語やライブラリの場合は例外を利用する。

### 5-b. 例外を補足するcatchは空にしない

- 例外を補足したらアプリの設計に従い処理を実装する。

### 5-c. 機密情報をコード平文で記載しない

- コード内に、パスワード、APIキーなどを平文で記載しない。
